# Among_Us_IRL
An in-real-life simulation of the game "Among Us," built on a Node.js server-client relationship.

## How it's done
You'll need **3 devices** acting as servers on the local network:
- 1 for reactor sabotage handling
- 1 for oxygen
- 1 for the actual server logic

Every player needs a mobile device to carry around and complete tasks on.

## Requirements
- [Node.js](https://nodejs.org/) (LTS version recommended)
- npm (comes bundled with Node.js)
- All devices connected to the same local network (unless using one of the remote-access methods below)

## How do I play
Download the project, install Node, run `npm install`, then host it. There are a few ways to do this — pick whichever fits your setup.

### 1. Node.js directly (recommended)

- Create a `.env` file at the project root:

```
PORT = {your port}
IP = {your device ip}
PROTOCOL = "http"
PASSWORD_HASH = {your password hash}
```

- Set `IP` to your device's IP address.
- Set `PORT` to some high 4-digit number, e.g. `8812` or `9432`.
- Leave `PROTOCOL` as `"http"` unless you're hosting behind a real TLS certificate (see the reverse-tunnel method below).
- Set `PASSWORD_HASH` to the hash generated by **bcrypt** at **10 salt rounds**.
- Start the server with `npm start` (or `node index.js`, depending on your `package.json`).

This is the simplest option and is best if everyone is going to be on the same Wi-Fi network.

### 2. PM2 (keep the server alive)

If you want the server to auto-restart on crashes or reboots (handy for longer game sessions), use [PM2](https://pm2.keymetrics.io/):

```bash
npm install -g pm2
pm2 start npm --name "among-us-irl" -- start
pm2 save
```

Useful commands:
```bash
pm2 logs among-us-irl   # view live logs
pm2 restart among-us-irl
pm2 stop among-us-irl
```

### 3. Docker

If you'd rather not install Node directly on the host device, containerize it:

```dockerfile
FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
CMD ["npm", "start"]
```

Build and run:
```bash
docker build -t among-us-irl .
docker run -d --env-file .env -p {your port}:{your port} among-us-irl
```

Or with `docker-compose.yml`:
```yaml
services:
  among-us-irl:
    build: .
    env_file: .env
    ports:
      - "{your port}:{your port}"
    restart: unless-stopped
```
```bash
docker compose up -d
```

### 4. Linux systemd service

To run the server as a background service that survives reboots:

```ini
# /etc/systemd/system/among-us-irl.service
[Unit]
Description=Among Us IRL Server
After=network.target

[Service]
WorkingDirectory=/path/to/Among_Us_IRL
ExecStart=/usr/bin/npm start
Restart=always
User=your-username
EnvironmentFile=/path/to/Among_Us_IRL/.env

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now among-us-irl
```

### 5. Windows Service

On Windows, use [NSSM](https://nssm.cc/) to run the server as a service instead of a terminal window:

```powershell
nssm install AmongUsIRL "C:\Program Files\nodejs\node.exe" "C:\path\to\Among_Us_IRL\index.js"
nssm start AmongUsIRL
```

### 6. Playing across separate networks (advanced, riskier)

The server is meant for **localhost / same-LAN use only**. If some players aren't on your Wi-Fi, you can expose it with a tunneling tool instead of opening ports on your router:

- **[ngrok](https://ngrok.com/)**: `ngrok http {your port}` — gives you a temporary public HTTPS URL that forwards to your local server.
- **[Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/)**: `cloudflared tunnel --url http://localhost:{your port}` — similar idea, no account strictly required for a quick tunnel.
- **[localtunnel](https://github.com/localtunnel/localtunnel)**: `npx localtunnel --port {your port}` — lightweight npm-based alternative.

> ⚠️ **This significantly increases the security risk described below.** Exposing the server to the public internet, even briefly, means anyone who finds the URL can interact with it — not just your players. Only use this for the duration of a single game session, and shut the tunnel down immediately afterward.

## Important security note
This server is meant to be hosted on **localhost only**. There are some serious vulnerabilities in the server because Im too lazy to fix the issues.

The client is **completely trusted**, (well, mostly) so if you play this game, keep in mind that anyone with decent cybersecurity skills can cheat — though they'd need external tools that aren't easily obtainable on mobile. This risk is much higher if you use one of the remote-access methods above, since the server is no longer confined to your local network.
